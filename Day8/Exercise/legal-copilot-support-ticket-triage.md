# Legal Copilot Support Ticket Triage (Likely Cause First)

Date: 2026-08-12  
Role lens: DWP engineer triaging Copilot support tickets

## Ticket-by-ticket assessment

| ID | Ticket | Likely cause (ranked, most probable first) | Fastest check (single first check) | Is this actually a Copilot bug? |
|---|---|---|---|---|
| 1 | Paralegal: Asked Copilot to summarise a client NDA in SharePoint, got “I don’t have access to that content.” The file is in a folder she’s never actually opened before, just heard about it in a meeting. | 1) permissions/access boundary 2) sensitivity label restriction 3) data indexing lag 4) license/client prerequisite issue 5) guest/external sharing limitation 6) genuine Copilot fault | Confirm whether the paralegal has direct permission to the NDA file or folder in SharePoint, not just awareness that it exists. | **No**. The message aligns with normal access enforcement. If she has never opened the folder and may not be assigned rights, permissions are the most likely cause. |
| 2 | New associate (started this week): Copilot in Outlook can’t find any of the case emails I need context on. | 1) data indexing lag 2) license/client prerequisite issue 3) permissions/access boundary 4) sensitivity label restriction 5) guest/external sharing limitation 6) genuine Copilot fault | Check when the user account and Copilot license were enabled relative to mailbox/content indexing time. | **No**. A new starter this week strongly points to mailbox/indexing warm-up or recent enablement rather than a Copilot defect. |
| 3 | Partner: Copilot surfaced and summarised a draft settlement from a matter I’m not assigned to. I didn’t know I could even see that folder. | 1) permissions/access boundary 2) data indexing lag 3) sensitivity label restriction 4) license/client prerequisite issue 5) guest/external sharing limitation 6) genuine Copilot fault | Verify the partner’s effective permissions on the source folder or document library in SharePoint. | **No**. This is more consistent with over-broad existing access than a Copilot bug. Copilot can ground on content a user is already permitted to access, even if that access was forgotten or wrongly granted. |
| 4 | Legal ops manager: All 40 people on the Legal team suddenly lost Copilot access this morning, worked fine all last week. | 1) license/client prerequisite issue 2) permissions/access boundary 3) data indexing lag 4) sensitivity label restriction 5) guest/external sharing limitation 6) genuine Copilot fault | Check one affected user’s Copilot license and service plan state in M365 admin first. | **Unclear**. Only move to bug status after admin checks and service health review. |
| 5 | Contract specialist: Copilot gives vague, generic answers when I ask about clauses in our contract templates library, doesn’t seem to actually read the documents. | 1) data indexing lag 2) permissions/access boundary 3) license/client prerequisite issue 4) sensitivity label restriction 5) guest/external sharing limitation 6) genuine Copilot fault | Pick one known template from the library and confirm it was recently added or changed and whether it appears searchable/indexed for the user. | **Unclear**. Generic answers can happen when the target content is not yet indexed or not retrievable in the current context. It is not enough evidence for a Copilot bug on its own. |

## Triage principle applied

Ranked ordinary enterprise causes ahead of product fault in every case. “Genuine Copilot fault” stays last and should only be considered after access, policy, licensing/client, guest-sharing, and indexing checks have been ruled out.
